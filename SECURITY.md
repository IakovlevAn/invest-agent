# Security model

## Ключевая граница доверия

Аналитический агент может только создать `ProposalBundle`. Этот объект не является
заявкой брокеру. Будущий исполнитель будет отдельным процессом и отдельным
пакетом, которому одному доступен торговый токен.

Подтверждение должно быть создано вне интерфейса аналитического агента и связано
с SHA-256 отпечатком точного пакета заявок. Любое изменение заявки делает старое
подтверждение недействительным.

## Секреты

- Refresh- и access-токены БКС нельзя передавать в чат.
- Токены нельзя хранить в Git, `.env`, SQLite или журналах.
- Для локального MVP read-only refresh-токен хранится только во временном файле
  внутри `/private/tmp` с правами `600`.
- Путь к файлу можно передавать в argv; значение токена — нельзя.
- Для чтения портфеля и для торговли используются разные refresh-токены.
- Аналитический процесс получает только read-only токен.
- Ротированный refresh-токен атомарно сохраняется в тот же временный файл до
  следующего сетевого запроса.

## Операции, которых нет в модели

- вывод денежных средств;
- перевод активов;
- изменение реквизитов и доступов;
- маржинальные операции;
- фьючерсы и опционы;
- рыночные заявки;
- покупка иностранных активов.

## Перед включением торговли

Нужны тесты одноразовости подтверждения, срока действия, изменения цены,
частичного исполнения, повторного запроса, сетевого таймаута, ответа `429`,
восстановления после сбоя и сверки фактической заявки с подтверждённой.
