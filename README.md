# Invest Agent

Локальный агент для управления российским инвестиционным портфелем с фокусом
на облигациях. Агент анализирует портфель, формирует объяснимые рекомендации и
готовит точный список лимитных заявок и фиксирует отдельное одноразовое
подтверждение владельца. Изолированный исполнитель может отправить только этот
неизменённый список после однозначного семантического подтверждения в Codex.

Пользовательский интерфейс — диалог с Codex в этом проекте. CLI ниже является
внутренним набором инструментов, который Codex использует для точных расчётов и
чтения портфеля.

Пользователю не нужно запускать терминал или читать JSON: все команды выполняет
Codex, а в диалоге возвращается готовый русскоязычный отчёт или рекомендация.

## Текущий статус

Реализован фундамент безопасного MVP:

- машинно-читаемый инвестиционный мандат;
- доменная модель портфеля и торговой рекомендации;
- независимая проверка ограничений;
- криптографическая привязка подтверждения к точному списку заявок;
- порт брокера только для чтения;
- нормализация официального ответа портфеля БКС;
- безопасная ротация refresh-токена в локальном приватном файле;
- обогащение облигаций карточками выпусков, торговыми данными и эмитентами MOEX;
- кредитные паспорта по официальному реестру рейтингов Банка России;
- фундаментальные паспорта по РСБУ юридического лица и графикам выплат MOEX;
- готовая рекомендация портфельного менеджера по свежим данным БКС, MOEX и ЦБ;
- проверка найденных выпусков, режима торгов, квалификации, лота и шага цены
  непосредственно по read-only API БКС;
- сценарная модель ключевой ставки ЦБ для флоатеров и длинных облигаций;
- точный список заявок с лотами, лимитной ценой, расчётной суммой с НКД и
  клиентским сроком действия;
- одноразовое подтверждение полного SHA-256 digest списка прямо в Codex;
- отдельный торговый BCS-клиент только для лимитной заявки, статуса и отмены;
- повторная предторговая сверка портфеля, справочника, сессии, котировки и стакана;
- детерминированные UUID заявок, локальный mode-600 журнал и защита от дублей;
- мониторинг исполнения, отмена остатка по клиентскому сроку и безопасная сверка
  после прерванного процесса без права создать новую заявку;
- три сценария: ничего не делать, вложить текущий кэш, ребалансировать к цели;
- детерминированные действия по выпускам и лимит 15% на эмитента после докупки;
- проектный Codex-скилл инвестиционного агента;
- тесты критичных запретов.

Торговый токен проверен отдельной авторизацией БКС. Реальные заявки ещё не
отправлялись: для этого нужен свежий точный список заявок и отдельное
подтверждение его полного digest.

## Принципы безопасности

- аналитический процесс не получает торговый токен;
- торговый refresh-токен хранится отдельно и загружается только командами
  проверки торговой авторизации, исполнения и сверки уже выставленных заявок;
- ни одна заявка не исполняется из текста рекомендации;
- разрешены только лимитные заявки;
- изменение цены, количества или инструмента меняет отпечаток предложения и
  требует нового подтверждения;
- заблокированные инструменты и запрещённые классы активов нельзя включить в
  заявку;
- вывод денег, переводы активов, маржинальные и производные операции не входят
  в интерфейсы приложения.

Подробнее: [SECURITY.md](SECURITY.md) и
[docs/INVESTMENT_MANDATE.md](docs/INVESTMENT_MANDATE.md).

## Локальное подключение БКС

Read-only refresh-токен хранится в `.local/secrets/` с правами `600`, а локальный
`.env` содержит только путь `INVEST_AGENT_TOKEN_FILE`. Оба пути исключены из Git.
Содержимое токена нельзя передавать в Codex, Git или вывод терминала:

```bash
uv run invest-agent portfolio --format json
```

После каждого обращения БКС ротированный refresh-токен атомарно записывается в
тот же приватный файл. `--token-file` остаётся доступен как явный временный
override.

Торговый refresh-токен хранится в отдельном mode-600 файле, путь к которому
задаёт `INVEST_AGENT_TRADE_TOKEN_FILE`. Значение токена не пишется в `.env`, Git,
аргументы команд или журнал исполнения.

После этого пользователь работает через Codex обычными фразами: «что у меня в
портфеле?», «куда вложить 50 тысяч?» или «оцени риск эмитента».

Основная команда для инвестиционного решения:

```bash
uv run invest-agent recommend --format json
```

Она за один запуск обновляет портфель БКС, показатели структуры, данные MOEX и
рейтинговые действия из репозитория Банка России, сканирует новые корпоративные
выпуски MOEX, перепроверяет действия по справочнику и котировкам БКС и строит
сценарии ключевой ставки. На выходе — действия по текущим облигациям, новые
кандидаты и сравнение трёх сценариев. Это только рекомендация: команда не создаёт
заявки и не является подтверждением сделки.

Когда пользователь после рекомендации просит подготовить сделку, Codex сам
формирует точный список заявок по свежему стакану БКС. В нём фиксируются ISIN,
тикер, режим торгов, сторона, число лотов и бумаг, лимитная цена, шаг цены,
расчётная грязная сумма с НКД, время котировки и срок действия. Предложение живёт
десять минут.
Число лотов дополнительно ограничивается показанным в стакане объёмом в штуках
по выбранной лимитной цене.
Подтверждение принимается отдельным однозначным сообщением обычным языком:
например, «подтверждаю выставление всех предложенных заявок» или
«покупаем предложенные активы». Пользователь не копирует digest — Codex сам
связывает сообщение с единственным активным предложением. «Ок», «готово»,
одиночное «давай», вопрос или согласие только с анализом подтверждением не
считаются. Любое изменение списка заявок требует нового digest и подтверждения.
Подтверждение создаёт локальную одноразовую квитанцию. После неё Codex запускает
исполнитель только с тем же digest: он повторяет все брокерские проверки,
выставляет лимитные заявки с детерминированными UUID, читает их статус и при
дедлайне отменяет остаток.
Один список может включать несколько точных действий из одного и того же свежего
отчёта и снимка портфеля; digest охватывает всю корзину.

Корзина нескольких заявок не является атомарной операцией БКС. Если поздняя
заявка не выставилась, исполнитель пытается отменить более ранние активные, но
уже совершённые сделки необратимы и всегда показываются как частичное исполнение.

Детерминированный аудит текущей структуры, управляемого контура и позиционной
концентрации вызывается Codex-командой:

```bash
uv run invest-agent audit --format json
```

Аудит не является торговой рекомендацией и явно перечисляет показатели, которые
невозможно оценить без рыночного, кредитного и исторического обогащения.

Официальные карточки выпусков и эмитентов, текущая эффективная доходность,
дюрация, спреды и показатели торгов Московской биржи:

```bash
uv run invest-agent bonds --format json
```

Команда использует публичный read-only MOEX ISS. Данные могут приходить с
задержкой; отчёт сохраняет время получения, торговый timestamp и прямые URL
источников. Доходность MOEX не считается прогнозом и не заменяет кредитный
анализ.

Кредитные паспорта текущих облигаций с рейтингами эмитента и точного выпуска:

```bash
uv run invest-agent credit --format json
```

Команда сначала обновляет портфель и данные MOEX, затем читает официальный
центральный репозиторий рейтингов Банка России по ИНН эмитента и точному ISIN.
Символы разных агентств сводятся только к широким диагностическим классам — это
не единый скоринг и не оценка вероятности дефолта. При CAPTCHA, изменении
контракта источника или неполном ответе отчёт показывает пробел данных и не
подменяет его выводом «рейтинга нет».

Годовая отчётность точного юридического лица и полный график выплат текущего
выпуска:

```bash
uv run invest-agent fundamentals --format json
```

Команда читает публичный ГИР БО ФНС по точному ИНН и MOEX ISS `bondization` по
текущему ISIN. Она сохраняет исходные строки РСБУ и отдельно считает прозрачные
диагностические показатели: долг, чистый долг, покрытие процентов, текущую
ликвидность, долг/капитал и приближённый FCF. РСБУ относится только к конкретному
юридическому лицу и не считается консолидированной отчётностью группы. Отсутствие
публичной отчётности отделяется от сетевой ошибки.
